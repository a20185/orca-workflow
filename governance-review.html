多 Agent 干活管理系统 · 评审说明

2026-11-06 · 依据同目录 governance-design.md 和 governance-tasks.md · 系统还没开始写代码
在建一套让多个 AI 一起写代码但不乱的系统：派活、接活、验收、合代码、收尾，全程有记录，谁都绕不过去。

为什么现在不够用

互相覆盖两个 Agent 同时改一个目录，谁后写谁说了算。
自己说自己行写代码的报「做完了」，没人复查。
目标越干越丢一个问题牵出十个，原来要干什么忘了。
回不去主任务子问题干完，主任务停在那没人管。
管不住 gitAgent 手里有 git 和 jj，说「别乱推」没用。
残局没人收干完留一堆终端、目录、容器。

以前怎么干活，留下什么

DSH 里跑通的三层分工一级管任务和并发，二级管一个任务，三级写代码，再加一个独立评审。这套分工整个保留。
现在 Orca 的流程GitLab 出票 → Orca 协调 → OpenCode 写 → 复审 → 人推送合并 → 手工清场。开终端、传消息、盯活这些能用，继续用。

要补的是硬规矩：谁验收、谁能动代码、怎么收尾——这些以前靠人盯着，现在交给程序判。

三条常走的岔路

出事了怎么办

协调者崩了新开一个，接上 gov 里的记录接着管，不用从头来。
干活的崩了先确认真停了，旧身份作废换人；旧的验收不作数，重来。
合并结果不确定停住，等人查清楚再动。系统不会自己偷偷重试。
界面 · 音视频这类必须人眼看、人确认。测试全绿也不算过。

谁能干什么

角色能干不能干
用户定任务、答疑、要人验收的亲自看，最后收结果不用盯着 AI 的逐字输出
协调者立任务、控制同时跑几个、处理异常不写代码，不验收
执行者接活、拆子任务、交活不能自己给自己验收
干活 Agent · OpenCode改任务书点名的文件、跑测试碰不了任务状态，碰不了别的目录
评审员 · Claude / Codex重跑验收、逐条对证据改代码没用，动了版本评审作废；立任务的、干活的、以前接过这活的，都不能当评审员
所有 Agent走受限入口交活、问问题、发消息谁都不能直接跑 git、jj、Orca 管理命令

现在做到哪了

  • 验证一：纯 jj 目录能不能接进 Orca，开终端、删目录都正常。
  • 验证二：受限入口能不能让 Orca 认出消息来自原终端，身份冒充不了。
  • 验证三：容器里 Agent 能改代码文件，但动不了 .jj 和 .git。
有一条验证不过，受控版本就停，先改平台，不拿「直接在宿主机上跑」凑合当受控。
