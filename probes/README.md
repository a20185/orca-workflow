# Phase 0 平台探针协议（T0.2–T0.4）

本 README 固定三项平台探针的执行纪律。探针执行者只读本文件与各自简报；停止条件的完整口径已按原文语义内嵌在本文，无需查阅其他计划文档。

三项探针是 [governance-design.md](../governance-design.md) §15 定义的实施阻塞项，不能用提示词或未验证假设代替。§15 总则：任一验证失败时，停止受控版本的后续实施，记录最小复现并修改对应平台能力；宿主直接运行通用 CLI 的模式只能用于开发测试，不能作为失败时的受控替代方案。

## 通用纪律（三项探针均须遵守）

1. **版本记录**：执行开始即在报告头部记录涉及组件的实际版本（Orca / jj / Docker），并与 governance-design.md §1 的本机基线（Orca 1.4.238、jj 0.41.0、Docker 29.6.1）对照。版本不一致时如实记录实际值，不猜测兼容性，不据此放宽本协议。本探针不涉及的组件记「不适用」。
2. **临时资源边界**：只允许使用临时目录（如 `mktemp -d`）与临时 Orca 资源（临时 folder/repo 注册、临时 run、临时 worker 会话）。禁止指向任何真实业务仓库；agents-impl 仓库及其任何 worktree 同样禁止。
3. **证据留存**：每个步骤在报告中留存四类字段——命令原文（含参数）、退出码、JSON 关键字段（只记录能判定步骤成败的 id / 状态等字段，不整段转储）、清理后状态（清理动作之后证明该资源已不存在的输出）。
4. **清理责任人**：每类资源在创建前登记清理责任人（默认探针执行者本人；执行简报另有指定时以简报为准）。清理按资源记账、不依赖探针结局：探针成功或中途失败，已创建的资源同样必须清理并记录清理后状态。
5. **真实模型确认**：凡执行中将调用真实模型的步骤，必须在执行前单独取得用户确认。当前协议下仅 T0.3 属于此类。若 T0.2 的「Agent 启动」步骤实际触发真实模型调用，先停止并按同一规则补确认后再继续。
6. **失败处理**：探针失败即按各自停止条件执行，不做失败时的受控替代；最小复现（命令、退出码、输出）记入报告，排查与复测在同一报告内追加。

## T0.2 纯 jj 目录的 Orca 注册/启动/删除

- **报告位**：`probes/orca-jj-folder.md`（由执行者创建并填写）。
- **验证目标**（governance-design.md §15 第 1 项）：纯 jj 目录能否注册为 Orca folder workspace，并完成 Agent 启动和删除。
- **版本记录**：必记 Orca 与 jj；Docker 不涉及时记「不适用」。
- **临时资源**：临时目录中创建的纯 jj 目录；Orca 内的临时注册项与启动产生的临时会话。两入口（以 T0.2 执行简报的定义为准）各自使用独立临时资源，不得共用。
- **证据字段**：注册、启动、删除各步骤的命令、退出码、`--json` 输出中的 id 与状态字段；删除后经 `orca repo list`（或等价查询）确认该项已消失的输出，作为清理后状态。
- **清理责任人**：在报告开头登记（默认探针执行者本人）。
- **真实模型**：按通用纪律第 5 条处理；启动步骤若实际触发真实模型调用，先补用户确认。
- **停止条件**（governance-tasks.md §2 Phase 0 口径）：两入口皆败 → T2.3 及其后任务停止；单入口结果按证据字段如实记录。失败时同时适用 §15 总则（记录最小复现并修改对应平台能力，不得以宿主直接运行通用 CLI 作为受控替代）。

## T0.3 受限启动器与 Dispatch 身份来源

- **标注**：需真实模型，已获用户授权（2026-11-07）。
- **报告位**：`probes/orca-guard-provenance.md`（由执行者创建并填写）。
- **验证目标**（governance-design.md §15 第 2 项）：Orca worker 注入的 executable 能否指向任务环境内的受限启动器；真实 CLI 经独立用户启动后能否保留原 worker 的 Dispatch 身份来源。
- **版本记录**：必记 Orca 与 Docker（受限启动器、独立用户涉及容器侧）；探针目录为 jj 目录时一并记 jj；不涉及的记「不适用」。
- **临时资源**：临时 Orca worker 会话、临时目录内的受限启动器、临时容器与临时用户。禁止指向任何真实业务仓库。
- **证据字段**：注入与启动各步骤的命令、退出码、worker/Dispatch 相关 JSON 关键字段（能证明身份来源仍指向原 worker 的字段）；会话、容器与启动器临时目录清理后的状态输出。
- **清理责任人**：在报告开头登记（默认探针执行者本人）。
- **真实模型**：本探针涉及真实 worker 启动，按上方标注执行，无需再次确认；超出标注范围的新增模型调用仍须单独取得用户确认。
- **停止条件**（governance-tasks.md §2 Phase 0 口径）：失败 → Track B 停止。失败时同时适用 §15 总则。

## T0.4 工作文件可写且版本元数据不可写

- **报告位**：`probes/workspace-metadata-acl.md`（由执行者创建并填写）。
- **验证目标**（governance-design.md §15 第 3 项）：Docker 内非 root 任务用户能否在正常工作目录写入文件的同时，被阻止修改、重命名和删除 `.jj` / `.git`。
- **版本记录**：必记 Docker；Orca 与 jj 不涉及时记「不适用」。
- **临时资源**：临时 Docker 容器，及其临时构建的镜像、容器内临时用户与临时工作目录。禁止挂载任何真实业务仓库。
- **证据字段**：工作目录写入（预期成功）与 `.jj` / `.git` 的修改、重命名、删除（预期被拒）各步骤的命令、退出码、错误输出关键行；容器与镜像清理后的状态输出。
- **清理责任人**：在报告开头登记（默认探针执行者本人）。
- **真实模型**：不涉及真实模型调用，无需确认。
- **停止条件**（governance-tasks.md §2 Phase 0 口径）：失败 → Track B 停止。失败时同时适用 §15 总则。
